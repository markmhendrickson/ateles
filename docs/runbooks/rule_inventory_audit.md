# Rule inventory: the private milestone audit

## Purpose

State where the complete rule-inventory measurement runs, when, how it is invoked, and what it produces,
now that no pull request runs it. Before ateles#1333 a `pull_request_target` workflow ran the full
measurement on every rule or foundation pull request, on an operator-owned self-hosted runner holding a
production Neotoma credential and the operator's local harness stores. That coupled ordinary pull requests
to one machine and failed on every matching pull request once the runner could not set up Python. The
operator ruled on 2026-09-28 that complete cross-store measurement is a private, milestone-driven audit, and
that pull requests are checked on GitHub-hosted runners only.

## Scope

Covers the private audit run by `execution/scripts/render_rule_inventory.py`, the hosted pull-request checks
that replaced the merge gate, and the status of the committed `docs/foundation/rule_inventory.md`. It does
not rule on the migration's target shape (`docs/foundation/migration.md` governs that), and it does not
cover provisioning any runner: no runner is part of this design.

## What moved where

| Need | Before | Now |
|---|---|---|
| Runtime rule delivery | Not checked by the inventory lane | GitHub-hosted effect tests in `.github/workflows/rule-sources.yml`: synthetic `agent_policy` rows through the real session hooks, agent loader, policy renderer, Codex hooks and the offline rule-delivery evals. A rule that stops reaching its surface turns them red. |
| Public consistency | Folded into the full cross-store equality gate | GitHub-hosted, same workflow: the repository's own rule sources (`CLAUDE.md`, `.claude/skills`, `.claude/hooks`) parse to rules with no private store reachable (`check_public_rule_sources.py`), and the hook-wiring reference equals `.claude/settings.json`. Foundation projections stay in `foundation-checks.yml`. |
| Private cross-store drift | Every covered pull request, on the self-hosted runner | This audit, run locally by the operator at milestones. |
| Migration evidence | The committed inventory, regenerated by the gate | The committed file is the historical Stage-0 snapshot; each milestone's render is kept privately. |

The retired workflow was `.github/workflows/canonical-rule-inventory.yml`. Its packager
(`package_rule_inventory_inputs.py`) and gate wrapper (`run_canonical_rule_inventory_gate.py`) are kept,
with their boundary tests, as the rollback path and for auditing a candidate tree as data.

## When it runs

Not on every pull request. Run it:

- when a rule-migration stage completes, or before one is declared complete;
- when the canonical boundary changes — a store is added, retired, or changes from authoritative to
  projection;
- before a ruling that relies on the duplication or divergence figures;
- whenever the operator asks for a fresh measurement.

## Where and how

On the operator's host, from a primary checkout of this repository at `origin/main` (trusted code, never an
unreviewed branch), with two values in the environment:

- `NEOTOMA_BEARER_TOKEN` — a read credential for the operator's **prod** Neotoma instance. The audit only
  reads. Load it the way the host already loads it for other tools; never print it.
- `RULE_INVENTORY_CANONICAL_REPOSITORY_ROOTS` — the host's canonical repository roots, path-separated, as
  defined in the inventory's method section. Host configuration, never committed.

Then, with `<private-dir>` a directory outside this repository that only the operator can read:

```bash
python3 execution/scripts/render_rule_inventory.py \
  --require-complete-measurement \
  --output <private-dir>/rule_inventory-$(date +%F).md \
  --private-diagnostics <private-dir>/rule_inventory-$(date +%F).locators.json
```

Add `--check` to also compare the measurement with the committed Stage-0 snapshot. Exit 1 from that
comparison means the rule estate changed since Stage 0, which is an audit finding, not a broken run.

Never run the renderer without `--output` for an audit: with no `--output` it overwrites the committed
snapshot, and committing that would republish store topology the redesign stopped publishing.

## What it outputs

- **Exit status.** 0: measured (and, with `--check`, equal to the snapshot). 1: with `--check`, the estate
  differs from the snapshot. 2: a safety screen or private write failed. 3: the measurement was incomplete
  (missing credential, unread store, zero rules) — the audit did not run, which is not a pass.
- **The render** at `--output`: the full inventory in the same public-safe form as the snapshot (rule values
  withheld, store locations projected to generic labels), written mode 0600. The renderer refuses a path
  inside the repository.
- **The locator map** at `--private-diagnostics`: which private source holds each NEEDS-SPLIT or diverging
  statement — local paths and entity ids, never statement values. Mode 0600, refused inside the repository.
- **A one-line summary** on stdout: rule count, statement count, duplication factor, divergence and
  NEEDS-SPLIT counts.

## Where the evidence lives

Keep each milestone's render and locator map together in the operator's private storage, named by date,
for as long as the milestone decision they support is open, and keep the render with the decision record
after that. Neither file is committed to a public repository. When a public issue needs evidence from an
audit, cite the aggregate headline figures only (rule count, statement count, duplication factor,
divergence count) — not the store table and never the locator map.

## The committed inventory

`docs/foundation/rule_inventory.md` stays in the repository as the historical Stage-0 snapshot, measured
2026-09-25. It is no longer regenerated into the public repository and no pull request compares against it.
Removing it from the working tree would not unpublish it, and the migration still starts from it. Its own
header says it is perishable; read its figures as of its measurement date.

## Rollback

Reverting the change that removed the workflow restores it exactly. That would also restore its dependence
on a self-hosted runner, which the operator ruled out as the solution, so a rollback is a stop-gap only.
