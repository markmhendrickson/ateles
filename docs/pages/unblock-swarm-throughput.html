Problems and their fixes

1

The operator’s escape hatch is silent

/confirm-gates-clear was posted on #711, #704 and #187. All three received, all three logged at INFO, none produced any GitHub comment — verified by reading every comment after each timestamp. Every guard early-return logs at log.debug while apis.py configures INFO, so a declined command is invisible on GitHub and in the log.

Fix — step 1. Always post a comment, including on every decline; raise those calls to INFO.

2

56% of open PRs cannot be gate-cleared at all

Gate state lives on the issue entity; a PR never carries gate_status. 46 of 82 open ateles PRs have no closure-keyword parent. No gate-clearing code reaches them.

Fix — step 2, operator-only. A policy choice: hard-block at PR-open, a bug fast path, or operator-gated merge.

3

A tax task reaches the payment executor

An assignee outside the 5-name route table falls through to keyword inference. Reproduced: resolve_skill(['finance'], assigned_to='picus') → monedula. Picus is the tax role; Monedula moves money. pavo→cicada too. A second defect compounds it — tags that are present but unmapped suppress text inference entirely, which is why this plan’s own step 1 is unroutable.

Fix — step 16. Both defects in one change. A blast-radius bug, not a routing miss — it must land before #597 adds routes.

4

Nothing sweeps for undispatched tasks

APIS_RECONCILE_ENABLED does not exist — zero hits repo-wide. SSE task.created is the only trigger, and TaskWatchdog explicitly excludes pending. A task created while the daemon is down is never dispatched by anything. 21,373 task entities exist in prod.

Fix — step 19. The claim+lease primitive is the sweep. Do not build an interim push sweeper.

5

Corvus can already be run — nothing decides to run it

Three disjoint execution mechanisms exist: dedicated daemons (12 of 37 agents), the GitHub pipeline, and the task path (5 skills). Corvus is reachable by none. But dispatch_role.py already runs any role with a SKILL.md, and the gate is already PR-independent — corvus is mapped to send_external_comms, already HIGH blast, with the approval loop closing over Telegram with zero GitHub.

Fix — steps 22–23. A claim predicate as simple as assigned_to == me. Do not build a new approval path or a daemon per agent.

6

Standing instructions die at every compaction

settings.json registers session_start.py against startup|resume|clear — excluding compact. The hook meant to preserve instructions is silent exactly when compaction eats them. One operator instruction was restated four times in a single session.

Fix — step 4 (#711). Itself blocked by problem 2 — the plan’s own reliability depends on a step inside the plan.

The model that survived verification

A throughput problem with a partial gate blockage, not a frozen system. 82 PRs open — but 11 merged today, and 36 opened against 9 merged. The swarm produces PRs ~4× faster than it merges them.

So the measure is merged-per-day reaching opened-per-day, not “the 82 are cleared.” A backlog refilling at 36/day is not fixed by draining it once.

Single-day sample. “4×” is today’s ratio, not an established rate.

The honest gap

Two reliability failures have no mechanism that fires when they occur: routing an agent-owned decision to the operator happens mid-turn, and reporting a snapshot as standing state is bound only inside the /where skill — it recurred in the brief that commissioned this plan.

The test is not that the machinery is written down, it is that it fires at the moment it applies. Strand B is not complete when #711 and #720 merge.
