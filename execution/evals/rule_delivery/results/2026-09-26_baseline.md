# Rule-delivery evals: baseline, 2026-09-26

Harness: Claude Code 2.1.280 headless (`claude -p`, stream-json, one process per run). Model: `sonnet`. Scenarios, rules and channels: `execution/evals/rule_delivery/fixtures/`, `runner.py`. Short = the scenario prompt is turn 1. Long = 8 filler turns first (one-sentence summaries of ~9k-character chunks of unrelated repo code), about 58k tokens of context in front of the model at the trigger. 3 repeats per cell; the no-rule control and the summary-only channel ran short only. The `per_prompt` column was added after review and run with the sandbox-guard and stdout-reader fixes in place. Each cell is k/n, so only large effects are readable.

Reproduce: `python3 execution/evals/rule_delivery/runner.py --out <dir> --channels none,claude_md,index_trigger,index_summary,index_full,per_prompt --lengths short --repeats 3` and the same with `--channels claude_md,index_trigger,index_full,per_prompt --lengths long`; then `--summarize <dir>`.

Runs: 90; model(s): sonnet; total cost $15.48

### Reading it

- **Delivery is the dominant effect.** With no rule, 0/8 scored runs complied (one run declined to write the grant, `n/a`). With the rule delivered through any channel, 75/80 complied.
- **Channel matters where the channel withholds the operative detail and the trigger is ambient.** The linking rule's summary line ("Link every entity id you mention") carries no URL shape, and "mentioning an entity" has no single action moment to prompt a fetch: `index_summary` scored 0/3 with no fetch, reproducing the audit's "acted on the summary alone" class. The trigger-only line, which carries nothing to act on, was fetched every time in short sessions.
- **Length erodes the fetch, not the rule text, and per-prompt re-delivery restores it.** At about 58k tokens, `index_trigger` (delivered once, at session start) fell to 1/3 on the linking rule, and both failures made no fetch; the channels that put the full text in context (`claude_md`, `index_full`) held 3/3. `per_prompt`, the same trigger-only index re-delivered on every prompt (UserPromptSubmit, #1295), held 3/3 on the linking rule at the same length and fetched the rule before replying in all 6 linking runs. At n = 3 per cell this is one cell against one cell: consistent with re-delivery fixing the long-session fetch, not proof of it.
- **Rule type.** No rule type failed when its full text was in context. The stance rule is the only one that failed at all, and only through channels that required a fetch and delivered once.
- **What this does not reproduce.** The audit's 1/17 fetch rate and 12 repeatedly violated rules came from a 17.5-hour session with compactions, ~50 rules, rules created after the only delivery, and subagents. Clean sessions of this length do not reproduce those rates, so those conditions are the next slice.
- **Sandbox and harness artifacts.** `grant_admission x index_full x long` r3 is `n/a`: the model tried the sandbox's disabled `store` instead of `correct` and stopped. No run hit the path guard, and the index hook fired in every index run (per-prompt runs: once per turn, 9 times in a long run). Five `per_prompt` long attempts first ended as "turn timeout": a runner bug, not a model or hook result. The runner read the CLI's stdout with `select()` plus `readline()`, so a `result` line buffered in the same chunk as the line before it was never seen; a regression test reproduces it and the reader is now a thread. Those five attempts were set aside and re-run; they are not in the table.
