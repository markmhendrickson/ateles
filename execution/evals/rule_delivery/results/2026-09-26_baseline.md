# Rule-delivery evals: baseline, 2026-09-26

Harness: Claude Code 2.1.280 headless (`claude -p`, stream-json, one process per run). Model: `sonnet`. Scenarios, rules and channels: `execution/evals/rule_delivery/fixtures/`, `runner.py`. Short = the scenario prompt is turn 1. Long = 8 filler turns first (one-sentence summaries of ~9k-character chunks of unrelated repo code), about 58k tokens of context in front of the model at the trigger. 3 repeats per cell; the no-rule control ran short only. Each cell is k/n, so only large effects are readable.

Reproduce: `python3 execution/evals/rule_delivery/runner.py --out <dir> --channels none,claude_md,index_trigger,index_summary,index_full --lengths short --repeats 3` and the same with `--channels claude_md,index_trigger,index_full --lengths long`; then `--summarize <dir>`.

Runs: 72; model(s): sonnet; total cost $11.47

### Reading it

- **Delivery is the dominant effect.** With no rule, 0/8 scored runs complied (one run declined to write the grant, `n/a`). With the rule delivered through any channel, 57/62 complied.
- **Channel matters where the channel withholds the operative detail and the trigger is ambient.** The linking rule's summary line ("Link every entity id you mention") carries no URL shape, and "mentioning an entity" has no single action moment to prompt a fetch: `index_summary` scored 0/3 with no fetch, reproducing the audit's "acted on the summary alone" class. The trigger-only line, which carries nothing to act on, was fetched every time in short sessions.
- **Length erodes the fetch, not the rule text.** At ~58k tokens, `index_trigger` fell to 1/3 on the linking rule, and both failures made no fetch; the channels that put the full text in context (`claude_md`, `index_full`) held 3/3 at the same length. The prohibition and verification rules, whose triggers are concrete actions (editing `mcp.json`, writing a grant), were fetched and followed 6/6 at both lengths.
- **Rule type.** No rule type failed when its full text was in context. The stance rule is the only one that failed at all, and only through channels that required a fetch.
- **What this does not reproduce.** The audit's 1/17 fetch rate and 12 repeatedly violated rules came from a 17.5-hour session with compactions, ~50 rules, rules created after the only delivery, and subagents. Clean sessions of this length do not reproduce those rates, so those conditions are the next slice.
- **Sandbox artifacts.** `grant_admission x index_full x long` r3 is `n/a`: the model tried the sandbox's disabled `store` instead of `correct` and stopped. No run hit the path guard, and the index hook fired in every index run.
