## Security repair (this round)

Bootstrap current-head review at `a19fc31d`/`d4339c25` reproduced a credential-boundary blocker: with GitHub delivery enabled and no explicit token supplied, the child retained ambient `GH_TOKEN`/`GITHUB_TOKEN` from the daemon process — a network-enabled child with no scoped identity fell back to whatever GitHub identity the host process happened to be carrying (on a host with an active `gh` keyring session, the operator's own account). Fixed by extending the fail-closed check from "empty token explicitly supplied" (pre-existing) to "any network-enabled dispatch with no *explicit* token, omitted or empty."

Self-review (`/code-review high`) on the first pass of this fix caught that the refusal was implemented as a raised `RuntimeError`, which broke this module's own documented contract ("failures never raise — callers get a `SkillResult`") and skipped `_run_provider_attempts`'s failover/cooldown/notification path, since its `await attempt(selected)` call has no try/except around it. Reworked as a preflight check returning a failed `SkillResult`, matching the existing `owns_pending_gate` refusal pattern in the same function, checked *before* the Stage 2 harness_event write so a refused dispatch leaves no audit trail claiming a subprocess started.
