Lets the individual PR-review lenses run on Fly runners, opted in per lens through `APIS_FLY_RUNNER_CLASSES`. Nothing moves until a class is listed.

Design basis: docs/foundation/principles.md

(Draft: keep the original PR's `Design basis:` line if it differs from this one.)

## Scope

- In: individual and missing-lens-recovery lens runs, seated read-only, with no Neotoma tools on the run. The lens returns its review between delimiters; the Mac posts it, as the lens's own App when it has one, otherwise under the existing shared identity.
- Out, cut in this round: the combined pm/qa/ux pass. It does not run return-only on Fly; it is pinned to the Mac (`runner="local"`) with the local prompt, exactly as on main. The `qa` lens also stays on the Mac and is not listed.

## Invariant

A response the gate reader would refuse is never accepted because a later step changed it. A returned response is judged as received, with the existing readers (`lens_own_verdict`, `sign_off_is_warranted` and the veto readers):

- any swarm marker anywhere in the response refuses it (the dispatcher adds the one marker itself);
- truncated output is refused before parsing, persistence, publication or sign-off;
- exactly one well-formed review section, at most one expectation section, nothing outside them that reads as a second verdict or header, and any veto in the whole response must be in the review;
- the review is the exact text between its delimiters, and the reader must decide the same about it before and after extraction;
- any failure is a failed lens run: nothing is persisted, posted or signed, and the bounded missing-lens sweep re-runs it.

## Tests

`test_lens_return_only_publication.py`, `test_fly_runner.py`, `test_fly_read_only_call_sites.py` cover each remaining path with refusal cases (no review, no post, no sign-off) and positive controls (valid response, Mac fallback, round trip through `lens_records`).
